# DECISIONS.md — deviations & choices where the spec allowed options

| # | Decision | Rationale |
|---|---|---|
| 1 | NestJS 11 (spec: "10+") | Current stable major; same architecture. |
| 2 | Prisma 6 + `@default(uuid(7))` | Spec asks uuid v7 "if available" — Prisma generates UUIDv7 client-side; no PG extension needed. |
| 3 | TailwindCSS 3.4 (not v4) | shadcn/ui + next-intl ecosystem fully stable on 3.4; deterministic config-file setup. |
| 4 | Zod v3 | nestjs-zod + @hookform/resolvers peer-range safety; shared package is the single source of truth as specced. |
| 5 | No `packages/ui` | Spec marks it optional; shadcn components live in `apps/web/src/components/ui` (display/portal have their own minimal styles). |
| 6 | Printables via print-CSS pages (prescription, visit summary, lab result, receipt, invoice) | Spec §11 mandates print stylesheets; avoids heavy server PDF deps. XLSX exports are server-side (exceljs). |
| 7 | JWT RS256 keys from PEM files (`.keys/`, gitignored), generated by `pnpm keys:generate` | Explicit, prod-friendly (mount secrets), no key material in env vars. |
| 8 | Telegram bot: grammY | Spec allowed grammY or Telegraf; grammY is lighter and better typed. |
| 9 | SMS default `SMS_PROVIDER=log` in dev | Spec: "sandbox/log mode"; Eskiz provider implemented behind `NotificationChannel` interface. |
| 10 | Appointment overlap guard: transactional `SELECT ... FOR UPDATE` on doctor-day | Spec offered this or exclusion constraint; transactional check keeps Prisma migrations clean and covers room conflicts too. |
| 11 | Local dev without Docker supported via `scripts/dev-local.mjs` (embedded Postgres + Redis binaries) | Developer machine may lack Docker (this one does); docker-compose remains the primary documented path. |
| 12 | Payme/Click/Uzum implemented behind `PaymentProvider` interface with sandbox-mode webhook handlers + signature verification; real merchant creds required to go live | Spec: "sandbox first". |
| 13 | Fiscalization: `FiscalizationService` interface + no-op stub | Spec explicitly requires stub only. |
| 14 | Inventory (M10): schema models included, endpoints/UI deferred | Spec: Phase 4 "keep schema-ready". |
| 15 | nestjs-zod v5 (`cleanupOpenApiDoc`) instead of v4 `patchNestJsSwagger` | v4 crashes against @nestjs/swagger 11 exports map (ERR_PACKAGE_PATH_NOT_EXPORTED). |
| 16 | TV display auth: per-branch long-lived display JWT (`POST /branches/:id/display-token`), pasted/QR-ed into the display app | Spec §10 requires JWT on the socket handshake; a staff login on a TV is impractical. |
| 17 | Roles as `User.role` enum + JSONB `permissionOverrides` (no Role/Permission tables) | Spec §5 defines roles as code-level permission bundles with per-user overrides; tables would duplicate the source of truth in `packages/shared/permissions.ts`. |
| 18 | Patient portal UI is Uzbek-only for v1 | Portal serves patients (uz default per spec); staff app carries full uz/ru/en i18n. |
| 19 | Portal identity = verified phone (OTP) across clinics; patient picks the clinic context per action | Same person can be a patient of many tenant clinics; phone is the natural join key. |
| 20 | uz-Cyrl messages generated by `scripts/uz-latin-to-cyrillic.mjs` from uz (ICU placeholders + brand tokens preserved); re-run after any uz text change | 1500+ kalitni qo'lda ikki marta yuritmaslik uchun; kirill tahririy sayqali ixtiyoriy. |
| 21 | Enum/status labels centralized in the `statuses` i18n namespace; `StatusBadge` auto-translates, `useEnumLabel()` for selects | Raw enum strings (WAITING, PAID, DOCTOR) were the source of mixed-language UI. |
| 22 | Login page shows a role-based demo-accounts panel unless `NEXT_PUBLIC_DEMO_LOGINS=false` | Demo/sotuv ko'rsatuvlari uchun; produksiyada bitta env bilan o'chadi. |
| 23 | Public clinic sign-up (`POST /auth/register-clinic`) has NO verification step — the director is signed in immediately on a `TRIAL_DAYS` (default 7) trial | Prod SMS is in log mode until Eskiz is configured, so an OTP gate would make sign-up unusable. Abuse is bounded instead: 3 sign-ups/hour/IP, one clinic per owner phone, unique clinic name, and every new trial is visible to the super-admin, who can suspend it. |
| 24 | Trial expiry is DERIVED from `ClinicSubscription.endsAt`, never written into `status` | Flipping an expired trial out of TRIAL/ACTIVE would make `assertPlanUserLimit` treat it as "no subscription → no limit", silently granting expired clinics unlimited staff. Deriving also removes the need for a scheduler. |
| 25 | Expiry degrades a clinic to READ-ONLY (safe HTTP methods pass, mutations get 402 `SUBSCRIPTION_EXPIRED`) rather than blocking login | A clinic must never lose sight of its own medical records over billing; and the owner has to be able to sign in to see why they are limited. Enforced globally by `SubscriptionGuard`, exempting SUPER_ADMIN, impersonation and `@AllowWhenExpired()` routes. |
| 26 | Super-admin extends a trial via `PATCH /platform/clinics/:id/subscription` (extendDays / endsAt) instead of re-using `POST .../plan` | `assignPlan` cancels the live row and creates a new one, which would reset `startsAt` and pile up history; extending in place keeps the trial's identity and makes "+7 days" mean 7 days. |
